Same shape as every other host: one catch-all, registered last.

```ts title="server.ts"
import { Elysia } from 'elysia'
import { createRscHandler } from '@rsc-kit/core/host'
import { assetsFrom, prerenderedFrom } from '@rsc-kit/core/files'
import * as engine from './build/dist/rsc/index.js'

const rsc = createRscHandler({
  engine,
  assets: assetsFrom('./build/public'),
  prerendered: prerenderedFrom('./build/static'),
})

new Elysia()
  .get('/health', () => ({ ok: true }))
  .all('*', async ({ request, status }) => (await rsc(request)) ?? status(404, 'Not found'))
  .listen(3000)
```

```sh
bun run build
bun run start
```

`request` is the standard `Request`, so there is no adapter in between and no
Elysia-specific module to import.

## Your API routes keep working

Declare them before the catch-all and they win outright:

```ts
new Elysia()
  .get('/api/posts', () => posts)
  .post('/api/posts', async ({ body }) => create(body))
  .all('*', async ({ request, status }) => (await rsc(request)) ?? status(404, 'Not found'))
  .listen(3000)
```

The RSC handler never sees those requests. Pages and API routes live in one
process, and neither knows about the other.

## What the catch-all returns

`rsc(request)` answers `null` for any url the route manifest does not claim,
which is what `?? status(404)` is for. Anything your app should handle itself —
including routes you add later — falls through untouched.
