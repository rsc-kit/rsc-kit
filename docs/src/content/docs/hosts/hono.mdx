One route, registered last.

```ts title="server.ts"
import { Hono } from 'hono'
import { createRscHandler } from '@rsc-kit/core/host'
import { assetsFrom, prerenderedFrom } from '@rsc-kit/core/files'
import * as engine from './build/dist/rsc/index.js'

const rsc = createRscHandler({
  engine,
  assets: assetsFrom('./build/public'),
  prerendered: prerenderedFrom('./build/static'),
})

const app = new Hono()

app.get('/health', (c) => c.json({ ok: true }))

// Last, so the app's own routes win. Anything left falls through to the RSC
// handler, and anything it does not claim is a real 404.
app.all('*', async (c) => (await rsc(c.req.raw)) ?? c.notFound())

export default { port: 3000, fetch: app.fetch }
```

```sh
bun run build
bun run start
```

`c.req.raw` is the standard `Request` Hono is holding. The handler takes that
and returns a `Response`, so there is no adapter in between and no Hono-specific
module to import — the same three lines work on any framework with a `Request`
in hand.

## Your API routes keep working

Register them before the catch-all and they win outright:

```ts
app.get('/api/posts', (c) => c.json(posts))
app.post('/api/posts', async (c) => { /* ... */ })

app.all('*', async (c) => (await rsc(c.req.raw)) ?? c.notFound())
```

The RSC handler never sees those requests. Pages and API routes live in one
process, and neither knows about the other.

## What the catch-all returns

`rsc(c.req.raw)` answers `null` for any url the route manifest does not claim,
which is what `?? c.notFound()` is for. Anything your app should handle itself —
including routes you add later — falls through untouched.
