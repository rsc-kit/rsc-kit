Two processes run in production: PHP, and the worker that renders React. This
covers keeping the second one alive — worker count, process managers, Docker
and a VPS deploy.

## Production Build

Always build RSC bundles before deploying:

```bash
# Build optimized server + client bundles
bun run build

# Verify the build output
ls bootstrap/rsc/     # Server bundle + manifests
ls public/build/rsc/  # Browser bundles (hashed filenames)
```

## Production Environment

```env title=".env"
RSC_ENABLED=true
RSC_SOCKET=/tmp/my-app-bridge.sock
RSC_WORKERS=4
```

Scale `RSC_WORKERS` to match your CPU cores. Each worker is a separate process with its own socket.

## Process Management

The worker must run alongside your PHP application. Use a process manager to keep it alive.

### Supervisor

```ini title="/etc/supervisor/conf.d/larabun.conf"
[program:larabun]
command=php /var/www/app/artisan rsc:serve
directory=/var/www/app
user=www-data
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/log/larabun.log
```

### systemd

```ini title="/etc/systemd/system/larabun.service"
[Unit]
Description=RSC worker
After=network.target

[Service]
User=www-data
WorkingDirectory=/var/www/app
ExecStart=/usr/bin/php artisan rsc:serve
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

## Docker

Run the worker alongside PHP in a multi-stage Docker setup:

```dockerfile title="Dockerfile"
FROM php:8.3-fpm AS php

# ... your PHP setup ...

COPY . /var/www/app
WORKDIR /var/www/app

# Install Bun
RUN curl -fsSL https://bun.sh/install | bash

# Build RSC bundles
RUN ~/.bun/bin/bun run build

# Start PHP-FPM and the worker
CMD ["sh", "-c", "php artisan rsc:serve & php-fpm"]
```

<Aside type="note" title="Separate containers">
  A Unix socket needs a shared filesystem, so two containers either mount a
  shared volume for it or switch transport:

  ```env title=".env"
  RSC_TRANSPORT=tcp
  RSC_HOST=rsc-worker
  RSC_PORT=7940
  ```

  With several workers the main ports run `port`…`port+N-1`, and the callback
  ports follow at `port+N`…`port+2N-1`.
</Aside>

## VPS Deployment

A typical deploy script:

```bash
#!/bin/bash
set -e

cd /var/www/app

# Pull latest code
git pull origin main

# PHP dependencies
composer install --no-dev --optimize-autoloader

# Build RSC bundles
bun run build

# Laravel cache
php artisan config:cache
php artisan route:cache

# Restart services
sudo supervisorctl restart larabun
sudo systemctl reload php-fpm
```

## Health Checks

The worker answers `ping` over the socket. You can verify the worker is running:

```php
// In a health check endpoint or console command
$bridge = app(RuntimeBridge::class);
$bridge->ping(); // Throws if worker is unreachable
```

## Checklist

- Run bun run build before every deploy
- Set RSC_WORKERS to match available CPU cores
- Use Supervisor or systemd to keep the worker alive
- Ensure socket path is writable by the web server user
- Cache Laravel config and routes in production
- Verify the worker with a health check endpoint
